# Contributing

```console
$ cargo test                 # 30+ integration tests, no agents needed
$ cargo fmt && cargo clippy --all-targets -- -D warnings
$ cargo run -- check         # the repo's own rules (see stele.toml)
```

CI (`ci.yml`) runs fmt + clippy + tests on Linux and macOS. The repo also
dogfoods itself: `stele.yml` is generated by `stele compile` and runs
`stele check` against your PR's change-set — the same gate your agents hit
locally. If a rule fires intentionally, acknowledge it in a commit:
`cargo run -- ack <rule-id> -m "why"`.

## The one rule about rules

Anything touching an enforcement channel (`hook.rs`, `emit.rs`, `wrap.rs`,
`conformance.rs`) should be validated against real harnesses, not just unit
tests — harnesses drift, and unit tests can't see that:

```console
$ cargo run -- conformance                 # all installed harnesses
$ cargo run -- conformance claude-code     # or one at a time
```

This costs real agent invocations (and for hermes, briefly rewires
`~/.hermes/config.yaml` with a restore). Paste the resulting table into
`conformance/RESULTS.md` with a date — that file is the project's empirical
memory, and it has caught a real bug on every sweep so far.

## Layout

- `src/substrate.rs` — the measurement substrate (the only code allowed to run git)
- `src/rules.rs`, `src/engine.rs` — rule evaluation, noise gates, telemetry
- `src/emit.rs` — per-harness response protocols (the only place dialects live)
- `src/hook.rs` — the single fail-open hook entrypoint
- `src/compile.rs` — stele.toml → every delivery channel
- `src/wrap.rs`, `src/devin.rs` — synthesized loops for hook-less harnesses
- `conformance/RESULTS.md` — what's actually been validated, when, and what broke
